## Findings

### M0-R1-F01  High  Code quality  Both setup scripts fail deterministically; criterion 1 not met
Location: `scripts/setup-wsl.sh:69-70`; `scripts/setup-windows.ps1:60,68,70,74`; `docs/reviews/evidence/m0/MANIFEST.md:16`
Problem: `setup-wsl.sh` requests `releases/latest/download/sops-v3.9.4.linux.${GOARCH}` and `age-v1.2.1-linux-…`; GitHub `latest` resolves to v3.13.3 and v1.3.2 whose assets embed their own version, so the URL cannot exist and `curl -f` under `set -e` aborts the `secrets` group on every machine. `setup-windows.ps1` uses `--exact` (case-sensitive) with four IDs that do not exist in the winget source; `Install-IfMissing` throws on the first one, so the `infra`, `cluster` and `secrets` groups cannot complete. The evidence pack verified only `bash -n`, which cannot catch either class of bug. The MANIFEST's caveat that IDs "may need adjustment" does not satisfy "documented scripts run".
Remediation direction: Pin releases in the URL path (`releases/download/v3.13.3/sops-v3.13.3.…`) with a single version variable per tool, or use `latest` only with unversioned asset names; correct the four winget IDs; add a dry-run/`--check` mode that resolves every URL and ID without installing, and put its output in the evidence pack.
Status: Open

### M0-R1-F02  High  Security  Recipient-removal procedure does not revoke access: data key is never rotated
Location: `docs/runbooks/secrets.md:64-76`; `.sops.yaml:17-18`
Problem: Both documents describe removing a recipient as "delete from `.sops.yaml`, run `sops updatekeys`". `updatekeys` re-wraps the existing data key for the new recipient set; the symmetric data key that encrypts the values is unchanged. A holder of a compromised age key who has decrypted the file once (or extracted its data key) can decrypt every future edit of that file, including the "rotated underlying secrets" the runbook says to change, because in-place edits keep the same data key. The runbook explicitly claims history exposure is the only residual risk (lines 73-75), which is false. Only `sops rotate -i` (new data key) closes this.
Remediation direction: Make `sops rotate --in-place` (then `updatekeys`) the mandatory step whenever a recipient is removed or a key is suspected compromised, and state that git history remains readable to the old key so the underlying credentials must also be changed.
Status: Open

### M0-R1-F03  Medium  Security  `.gitignore` blocks the documented encrypted-tfvars path; docs contradict config
Location: `.gitignore:29-30`; `.sops.yaml:34`; `docs/runbooks/secrets.md:56-57`; `infra/README.md:13-14`
Problem: `**/*.tfvars` with only `!**/*.example.tfvars` re-included means `infra/terraform/hetzner/secrets.enc.tfvars` — the exact filename used in the runbook — is ignored (`git check-ignore` confirms). The `.json` variant is not ignored, so behaviour differs by extension. At M2 the operator will either `git add -f` (habit-forming and dangerous with a plaintext `.tfvars`) or discover the docs are wrong.
Remediation direction: Add `!**/*.enc.tfvars` and `!**/*.enc.tfvars.json` negations directly under the `*.tfvars` rule, and state in `infra/README.md` that plaintext tfvars are ignored while `.enc.` variants are tracked.
Status: Open

### M0-R1-F04  Medium  Security  SOPS CI check has false negatives on covered paths and matches on a substring
Location: `.github/workflows/hygiene.yml:42-52`; `.sops.yaml:34,45`
Problem: The CI regex `\.(enc|secret)\.[A-Za-z0-9]+$` does not match `*.enc.tfvars.json` (covered by `.sops.yaml:34`) or `*.enc.auto.tfvars`; a plaintext file at either path is committed silently. The encryption test itself is `grep -Eq '^sops:|"sops":|^\[sops\]|ENC\['`, so any plaintext file containing the string `ENC[` (e.g. a comment) passes. Conversely `*.secret.<ext>` outside `k8s/` is flagged by CI but has no creation rule, so `sops -e` refuses it — a false positive by design mismatch.
Remediation direction: Derive the path list from `.sops.yaml` itself (e.g. `yq '.creation_rules[].path_regex'`) and test encryption with `sops filestatus` or a decrypt-to-null attempt, not a substring grep.
Status: Open

### M0-R1-F05  Medium  Security  Evidence directory excluded from secret scanning
Location: `.gitleaks.toml:9-11`
Problem: `docs/reviews/evidence/.*` is allow-listed wholesale. Evidence packs are, by the process defined in `CRITIC.md`, where command outputs (`terraform plan`, `kubectl describe`, rendered manifests, logs) get committed — precisely where tokens, connection strings and kubeconfig fragments leak. Excluding it removes the control from the one directory most likely to need it.
Remediation direction: Remove the path allowlist; if a specific evidence artefact produces known false positives, allow-list that file or fingerprint.
Status: Open

### M0-R1-F06  Medium  Security  Notebook `auth_hash` stores the bearer value verbatim
Location: `docs/adr/0009-notebook-crypto-and-language.md:31-33`
Problem: `authProof = base64url(SHA-256(authKey))` is "sent on mutating requests and stored by the server as the notebook's `auth_hash`". The stored value *is* the credential the client presents, so a database or backup leak (S3 bucket, WAL archive, restore-drill namespace) lets anyone overwrite or delete every notebook's ciphertext. Confidentiality survives; integrity and availability do not, and the ADR's "server can never read content even if compromised" framing hides this.
Remediation direction: Store `SHA-256(authProof)` (or an HMAC under a server key) and compare hashes, so the DB never holds a replayable value; document the residual risk that Cloudflare and the live server see the proof in transit.
Status: Open

### M0-R1-F07  Medium  Reliability  Single control plane risk understated: etcd is a single copy and no backup is planned
Location: `docs/adr/0004-talos-on-hetzner-via-hcloud-k8s.md:52-54`; `docs/architecture.md:64-65`; `git grep -i etcd` → no results
Problem: Both documents describe the risk as "API-server downtime, workloads keep running". With one CX23 the only etcd member lives on a single Hetzner root disk; losing it loses every PV binding, CNPG `Cluster` object, Argo state and certificate — a full rebuild from Git plus data restore from S3, not an API blip. The word etcd does not appear anywhere in the repository, and no `talosctl etcd snapshot` schedule or restore path is mentioned in the runbook index.
Remediation direction: Rewrite the consequence honestly (etcd single copy, node loss = cluster rebuild), add an etcd snapshot-to-S3 runbook to the M2/M3 runbook list, and state the RTO the operator accepts.
Status: Open

### M0-R1-F12  Medium  Security  Cloudflare Access enforced only at the edge; no origin-side assertion planned
Location: `docs/adr/0005-cloudflare-tunnel-only-ingress.md:20-23,28-30`; `docs/adr/0014-…md:19-21`
Problem: The tunnel has a single catch-all `*.ivanpanev.net` rule and Access policies are per hostname. Any hostname CNAME'd to the tunnel without a matching Access application (typo, Terraform drift, manual DNS record) reaches the Gateway protected only by the app's own login. ## Dimension notes

### Code quality — 5
The documentation is well structured, consistently formatted, and the LF/CRLF normalisation is correct and verified (`git ls-files --eol`). The scripts are the problem: two guaranteed 404s and four wrong package IDs mean neither setup script completes (F01), the Windows script cannot upgrade and will abort on `corepack` (F13), the CI regex disagrees with `.sops.yaml` (F04), and the runbook's grep disagrees with both (F14). The evidence pack tested syntax only; none of these bugs required a network to find except the IDs, and those were flagged as "may need adjustment" rather than checked. Duplicated version tables across two scripts and one doc (F10) are already drifting.

### Scalability — 7
Little to judge in a scaffold, but the decisions that touch load are considered: notebook caps and rate limiting are specified with numbers (ADR-0009), Loki SingleBinary and Prometheus retention are explicitly sized as small with a named migration path (ADR-0007), and the static site is decoupled from cluster load entirely (ADR-0002). Nothing here would need to change at 10x for a personal platform. Cardinality (per-IP token buckets, Loki labels) is not yet discussed; expected at M4/M5.

### Reliability — 6
Failure handling in the ADRs is mostly honest (CNPG single instance restarts, Loki single pod, Cloudflare dependency) and backups are designed in from day one with a scheduled restore drill (ADR-0008). The one place it is not honest is the one that matters most: the single control plane is presented as an API-availability inconvenience, with etcd never mentioned and no snapshot plan (F07). Prometheus TSDB loss is accepted in writing, which is fine. Idempotency of the scripts is claimed but partial (F13).

### Future-proofing and migration readiness — 7
Portability discipline is strong: provider-bound pieces are confined to `infra/terraform/cloudflare` and the CCM/CSI layer, state is constrained to Postgres/S3 with explicit migration steps, SOPS recipients are cluster-independent, and `TARGETARCH` is required now for a later Arm move. I verified the Astro 6 date and Node floor, the Hetzner 15-June-2026 price table, CX23/CX43 prices, and the k8s-monitoring v4 feature names (`podLogsViaLoki`, `clusterEvents`); all correct — that is rare and deserves credit. Points lost for stale toolchain floors that contradict the cluster targets (F10), no chart-update mechanism (F11), and three ADRs that are plans rather than decisions (F08).

### Security — 5
The supply-chain basics are right: both action SHAs resolve to the tagged commits, gitleaks runs on full history, the placeholder recipient cannot encrypt anything by accident, and the secrets model (encrypted in Git, age recipients per principal) is sound. But the rotation procedure the operator will follow under pressure does not revoke a compromised key (F02), the evidence directory is exempt from scanning (F05), the workstation bootstrap pipes unpinned scripts into `sh` (F09), the notebook stores its bearer value verbatim (F06), and there are concrete gaps between `.sops.yaml`, `.gitignore` and CI (F03, F04). Access is edge-only with no stated origin assertion (F12). None of these is exploitable today because nothing is deployed, which is exactly why they are cheap to fix now.

### Operability — 6
An operator arriving cold finds a clear map (`architecture.md`), an indexed ADR set, a runbook index that names what will exist and when, credential scopes spelled out, and a toolchain page that records the workstation's virtualisation constraint. The gap is that the operator's first two actions — run the setup script, commit an encrypted tfvars — both fail against the documentation (F01, F03). Runbook and CI contradict each other on timing (F14), and the evidence pack was assembled with tooling that corrupted one artefact (F16).

## What was done well
- Third-party actions are pinned to commit SHAs that I independently resolved to the claimed tags via the GitHub API (`hygiene.yml:28,31,40,58,73`); this closes the tag-mutation attack on CI.
- Factual claims in the ADRs are current and correct for September 2026: Astro 6.0 on 2026-03-10 with Node ≥ 22.12, Hetzner's 15 June 2026 repricing (CX23 €5.49, CX43 €15.99, CPX/CCX ~2.1–2.75x), Ingress NGINX retirement, k8s-monitoring v4 feature names. A design built on wrong versions fails later; this one is not.
- ADR-0009's rejection of a per-notebook server-fetched salt is argued correctly: with passcode-only access the lookup key must be derivable from the passcode alone, so a random salt only adds one KDF evaluation per confirmed hit. The trade-off is stated instead of hidden.
- `.sops.yaml` uses `encrypted_regex: ^(data|stringData)$` for Kubernetes secrets, keeping manifests diffable and KSOPS-renderable, and the placeholder recipient is syntactically invalid so an unconfigured clone cannot silently encrypt to nothing.
- Line-ending policy is implemented, not just declared: `.gitattributes`, `.editorconfig`, and CI agree, and the index is uniformly LF (`git ls-files --eol`), with PowerShell files correctly excepted.
- The open-decisions register (ADR-0001) gives every deferred choice a deadline and a default, which prevents "we'll decide later" from silently becoming "we never decided".
