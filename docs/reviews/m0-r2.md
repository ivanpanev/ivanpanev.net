### M0-R1-F01  High  Code quality  `setup-wsl.sh` still fails deterministically in the default invocation; criterion 1 not met
Location: `scripts/setup-wsl.sh:118-126` (go group), `:52` (`head_ok`), `:55-62` (`fetch` in check mode); `docs/reviews/evidence/m0/setup-wsl-check.txt:7`
Problem: The round-1 bugs are fixed (sops/age URLs, all 17 winget IDs verified by me). But the Go checksum URL `https://go.dev/dl/${f}.sha256` returns HTTP 200 with an HTML "Redirecting to documentation" page, not a hash; go.dev only redirects the tarball itself to `dl.google.com`. On a real run, `echo "$(cat "$TMP/$f.sha256")  $TMP/$f" | sha256sum -c` fails with "no properly formatted SHA256 checksum lines found" and `set -e` aborts. With the default `all`, nothing after `go` (Terraform, Packer, hcloud, kubectl, Helm, kustomize, talosctl, argocd, kubeconform, cosign, sops, age, gh) is installed. The evidence pack could not catch this because `--check` (`fetch` → `head_ok`) accepts any 2xx; go.dev returns 2xx HTML for any filename (a bogus `go9.99.9` tarball redirects to a 404, but any `.sha256` returns 200). Same failure class as round 1, one URL, fails closed. Fix is one line, but the milestone's criterion is "the documented scripts run".
Remediation direction: Fetch the checksum from `https://dl.google.com/go/${f}.sha256` (or use the `?mode=json` listing, which includes `sha256` per file), and make `--check` download every checksum file and assert it contains a 64-hex token for the artefact rather than trusting HTTP status; put a full-install transcript from a Linux machine in the round-3 evidence pack.

## What was done well
- `verify()` (`setup-wsl.sh:66-76`) is correct for `sha  name`, `sha *name` and bare-hash files, escapes dots in the asset name, anchors on end-of-line so `cosign-linux-amd64` does not match `cosign-linux-amd64_3.1.3_linux_amd64.sbom.json`, refuses `_out/`-prefixed names it was not told about, and fails closed on HTML — I tested each of these; and the twelve real checksum files use exactly the asset names the script passes.
- The rotation runbook now teaches the data-key/recipient-wrapping model before the commands (`secrets.md:66-78`), and the drill uses `sops rotate -i --rm-age`, which is the single atomic primitive that revokes a recipient; every flag exists in the pinned sops version.
- ADR-0005's remediation is defence in depth that fails closed: per-hostname ingress with `http_status:404` catch-all, `originRequest.access` JWT validation at cloudflared (a documented feature), and a Terraform invariant that forbids the "no Access, not public" third state.
- `scripts/versions.env` is genuinely the single source: four scripts parse it, Renovate updates it, and the two pins that must follow the cluster (`PIN_KUBECTL`, `PIN_TALOSCTL`) are excluded from automation with the reason in the config's own description.
- `sops-files.sh` makes `.sops.yaml` the only definition of "must be encrypted" and CI asks SOPS itself; the runbook and CI literally share the command, so they cannot disagree again.
- ADR-0004's etcd consequence separates RTO (4 h, cluster rebuild) from RPO (CNPG WAL archiving, minutes) instead of conflating them — the distinction an operator needs when deciding whether to buy the third control-plane node.
- The evidence pack is now reproducible: every transcript I re-ran matched, `tree.txt` is identical to `git ls-files`, and the MANIFEST states what could not be executed here and where it runs instead.
