Date: 2026-09-16
Scope: Ship the public site as a fully static Astro 7 build (React islands, MDX, sitemap, RSS, Tailwind, Pagefind, CSP API, Fonts API) with layouts, content collections, three offline tools, PGP/WKD/verify, Cloudflare Workers Static Assets deploy config, and GitHub Actions CI. No Node/Workers SSR adapter.

## Verdict

Overall: 8 — FAIL
Code quality: 8 | Scalability: 9 | Reliability: 7 | Future-proofing: 8 | Security: 8 | Operability: 8

The static site is a real, ADR-compliant artefact: no adapter, hash-only CSP, honest crypto, fail-the-build signing contract, and Lighthouse 100 on the sampled pages. It fails this round because one Medium is open: the no-flash head script swallows storage errors before it paints `data-theme`/`data-skin`, and the unit test for that path only asserts “does not throw”. Fix that (apply attributes first, then persist; assert attributes in the blocked-storage test) and this is an 8 that can pass. A 9 also wants the www Host-header test the evidence pack claimed, and LHCI actually waiting on the port instead of timing out.

## Findings

### M1-R1-F01  Medium  Reliability  Head script swallows storage errors before painting theme
Location: `apps/web/src/lib/theme.ts:56-67`; test `apps/web/tests/unit/theme.test.ts:102-105`; tokens `apps/web/src/styles/skins.css:15-30` (canvas/fg only under `[data-skin]`)
Problem: The inline head script wraps everything in `try/catch` that ignores the error. On first visit it calls `localStorage.setItem` *before* `setAttribute("data-skin")`. If storage throws (Safari private mode, blocked storage), the catch fires with no `data-theme`/`data-skin`. `--canvas`/`--fg` are then unset and the first paint is unstyled. The unit test named “never throws when storage is blocked” does not assert that attributes were applied, so the hole is green.
Remediation direction: Set `data-skin`/`data-theme` first, persist afterwards in an inner try, and assert attributes in the blocked-storage test. ThemeToggle already does this split correctly.
Status: Open

### M1-R1-F02  Low  Operability  Evidence pack claims a www-redirect e2e that does not exist
Location: `docs/reviews/evidence/m1/MANIFEST.md:26`; `apps/web/tests/e2e/` (no `www` match); redirect itself is `apps/web/public/_redirects:1-2`
Problem: The pack says `headers.spec.ts` exercises `www` → apex under workerd. There is no such test. The `_redirects` rule is Host-based and will not fire against `127.0.0.1`. A false claim in the evidence pack is how operator-verify steps get skipped.
Remediation direction: Add a `Host: www.ivanpanev.net` request test (or drop the claim) and keep live confirmation on the first deploy.
Status: Open

### M1-R1-F03  Low  Reliability  Lighthouse CI does not wait for wrangler to be ready
Location: `apps/web/lighthouserc.cjs:10-12`; `docs/reviews/evidence/m1/lighthouse.txt:8-10`
Problem: `--log-level warn` hides wrangler’s “ready/listen” banner. LHCI still waits on `/listen\|ready/i`, times out, then proceeds. The comment claims LHCI will poll the port; it does not set `startServerReadyPattern` (or an equivalent URL check). Playwright e2e does the right thing (`playwright.config.ts:25-32` waits on `url`). The Lighthouse AC gate is the sloppy one.
Remediation direction: Point LHCI at the same URL-ready check Playwright uses, or lower wrangler log level so “Ready” is printed.
Status: Open

### M1-R1-F04  Low  Code quality  `urls.ts` and `tools.ts` have zero unit coverage
Location: re-run coverage table: `lib/urls.ts` 0% lines (8-16), `lib/tools.ts` 0% lines (2); `apps/web/vitest.config.ts:11-13`
Problem: `canonicalPath` is the single place that strips `.html` from `build.format: 'file'` pathnames (`apps/web/src/lib/urls.ts:7-11`). check-dist catches some leaks after the fact; nothing tests the helper. A one-line regression publishes `.html` canonicals and OG URLs.
Remediation direction: Add a few cases for `/`, `/index.html`, `/blog/x.html`, trailing slashes. Keep the registry file excluded if you do not want to test data.
Status: Open

### M1-R1-F05  Low  Future-proofing  Content schemas use deprecated `z` from `astro:content`
Location: `apps/web/src/content.config.ts:1`; `pnpm check` → 21 hints `ts(6385) 'z' is deprecated`
Problem: Astro is already warning. Leaving this until it becomes an error will collide with an unrelated content change.
Remediation direction: Import `z` from the supported module Astro documents for v7 ( astro/zod or equivalent) while the migration is still mechanical.
Status: Open

### M1-R1-F06  Low  Operability  WKD/key absence is warn-and-succeed forever
Location: `apps/web/src/integrations/wkd.ts:35-37`; re-run `pnpm build` → `[WARN] [ivp:wkd] no public key at src/pgp/publickey.asc; skipping`
Problem: Fail-open is correct *until* the ceremony. After `publickey.asc` is committed, deleting or renaming it will drop WKD and `/pgp/ivan.asc` while CI stays green. `check-dist.mjs:32` does not require WKD files.
Remediation direction: Once the key is in git, fail the build if it is missing (env flag or “file was present in the last release” check). Until then this stays an operator action.
Status: Open

### M1-R1-F07  Low  Security  Preview job interpolates the PR title into the wrangler command
Location: `.github/workflows/web.yml:157`
Problem: `command: versions upload --tag pr-${{ github.event.pull_request.number }} --message "${{ github.event.pull_request.title }}"` puts an attacker-influenced string (same-repo PR, including Renovate) into the action input. If wrangler-action shells that string, it is command injection. Same-repo-only reduces blast radius; it does not make the pattern acceptable.
Remediation direction: Pass a fixed message (`pr-N`) or the SHA. Do not interpolate `pull_request.title`.
Status: Open

### M1-R1-F08  Low  Operability  `architecture.md` still describes Astro 6
Location: `docs/architecture.md:29` “Astro 6 static build”; ADR-0003 and the tree are Astro 7
Problem: The living map an on-call stranger reads is already wrong on day one of M1. That is how later milestones inherit a stale picture.
Remediation direction: Update the layer table (and the M1 row in the milestone log) when this review lands.
Status: Open

### M1-R1-F09  Low  Security  security.txt `Encryption` points at an HTML page
Location: `apps/web/public/.well-known/security.txt:4` `Encryption: https://ivanpanev.net/pgp`
Problem: RFC 9116’s Encryption field is meant to be a key, not a page. Until the ceremony `/pgp` is a placeholder, so a client that fetches this URI does not get a key.
Remediation direction: After the ceremony, point it at `https://ivanpanev.net/pgp/ivan.asc` (and keep `/pgp` in Contact/Policy if you want a human page).
Status: Open

### M1-R1-F10  Nit  Code quality  HTML compressor eats the space before the licence link
Location: `apps/web/src/components/Footer.astro:8-10`; `dist/index.html` contains `Text is<a class="underline`
Problem: `compressHTML: 'jsx'` collapses the newline between the text node and the `<a>`, so the footer reads “Text isCC BY 4.0”.
Remediation direction: Put an explicit `{' '}` (or `&nbsp;`) between the sentences, as ProseLayout already does for similar joins.
Status: Open

## Dimension notes

### Code quality — 8
Modules are small and named for their job. The interesting logic (subnet, secrets, WKD hash, signed-posts pairing) is unit-tested, including a chi-square check and a WKD draft vector. Islands keep `location`/storage inside `useEffect`. Gaps that keep this off 9: `urls.ts` untested, the blocked-storage test that does not check attributes, 21 deprecated-`z` hints, and the footer space.

### Scalability — 9
This is a directory of files on an edge cache. There is no origin compute, no N+1, no unbounded store. React ~66 KB gzip on every page because ThemeToggle is a global island (`Header.astro:37` `client:idle`); Lighthouse still scores 100, so it is a cost not a blocker. 100× traffic is Cloudflare’s problem.

### Reliability — 7
Happy path is careful: digest mismatch fails the build, private keys fail the WKD publish, `/verify` returns `valid: false` on tamper, e2e runs against workerd not `astro preview`. The pain is the theme script’s all-or-nothing try/catch (F01) and an LHCI start that does not actually wait (F03). Signing and WKD are fail-open until the ceremony; that is documented and accepted for bootstrap, not for forever.

### Future-proofing and migration readiness — 8
Matches ADR-0002 (static assets, no Worker logic, no KV/D1), ADR-0003 (Astro 7, React-only islands, native view transitions, hash CSP, Fonts API), ADR-0011 (custom WikiLayout), ADR-0012 (path-filtered `web.yml`, action SHAs). TypeScript `~6.0` pin is in the ADR and the backlog. Output is a file tree; nginx/Caddy later is a copy. Deprecated `z` and the stale architecture sentence are the debt.

### Security — 8
`default-src 'none'`, hash-only `script-src`, `style-src-elem` hashed, `style-src-attr 'unsafe-inline'` only for Shiki (ADR-0003), self-hosted fonts, no runtime third parties. `getRandomValues` + rejection sampling is implemented and tested, not commented. WKD refuses private keys; Verifier refuses pasted private keys. `sign-post.sh` never hands the key to Node. Actions are SHA-pinned; preview is same-repo-only; `permissions: contents: read`. Leftovers: PR-title interpolation, `wasm-unsafe-eval` on every page, security.txt Encryption URI.

### Operability — 8
`docs/runbooks/pgp-key-ceremony.md` is a 3 a.m. document: generate, backup, publish, WKD curl, locate-keys, sign-post, renew, revoke. `apps/web/README.md` lists the exact commands and the “do not reuse wrangler” trap. Rollback is revert + the same artefact pipeline. Missing: a www test they claimed to have, post-deploy smoke that does not hit WKD, and any live `web.yml` URL (operator). That is not a design hole; it is unrun CI.

## What was done well
- Deploying the verified `dist` artefact (`web.yml:188-199`) instead of rebuilding on the deploy job removes a class of “CI was green, production was a different tree” failures.
- Third-party actions are full-SHA pins with version comments; `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` is in fact v7.0.1 and `cloudflare/wrangler-action@ebbaa1584979971c8614a24965b4405ff95890e0` is in fact v4.0.0 (ADR-0012).
- Secret generation is actually uniform: injectable RNG, rejection sampling, inclusion-exclusion entropy, and a chi-square test — not `Math.random` with a comment.
- signed-posts fails the build on `signed: true` without `.asc` and on digest mismatch, so a signed post cannot ship unsigned or edited. The naive frontmatter parser is tested for CRLF.
- WKD uses the draft’s `Joe.Doe` test vector and publishes binary keys, not ASCII armour, at the direct-method path.
- CSP is hash-only and checked three ways (Astro emit, `check-dist`, e2e console/CSP assertions against workerd). Native view transitions were chosen specifically so `ClientRouter` would not re-execute inline scripts under that CSP.
- E2E targets `wrangler dev` (same html_handling, `_headers`, 404 page as production) rather than `astro preview`.
