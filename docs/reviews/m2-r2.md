## Findings

### M2-R1-F03  Medium  Reliability  Notes-api rate-limit defaults may not apply
Location: `infra/terraform/cloudflare/rate_limit.tf:1-22`; `infra/terraform/cloudflare/variables.tf:91-105`; `docs/runbooks/cluster-bootstrap.md:93-95`
Problem: Round 1: `period`/`mitigation_timeout` defaulted to 60, which Cloudflare Free commonly rejects. Round 2 defaults are 10 / 10 / 10, the variable description and resource comment record Free vs Pro, and `rate_limit_period` may only be 10 or 60.
Remediation direction: Keep the Free-legal defaults; do not raise `period` to 60 without a Pro zone.
Status: Fixed in round 2

### M2-R1-F02  Medium  Security  Tunnel-token SOPS encrypt misses `.sops.yaml`
Location: `docs/runbooks/cluster-bootstrap.md:102-145`; `.sops.yaml:29-36`; `docs/runbooks/secrets.md:25-39`
Problem: Round 1 wrote `/tmp/tunnel.secret.yaml`, which matches no creation rule. Round 2 writes `k8s/infrastructure/cloudflared/tunnel.secret.yaml` and encrypts in place (bash and PowerShell), which matches `^k8s/.*\.(enc|secret)\.ya?ml$`. `sops filestatus` is mandatory before commit.
Remediation direction: Keep encrypting on the Git path; do not encrypt under `/tmp`.
Status: Fixed in round 2

### M2-R1-F01  Medium  Operability  Full destroy cannot keep protected buckets
Location: `docs/runbooks/cluster-teardown.md:28-47`; `infra/terraform/hetzner/buckets.tf:15-19`
Problem: Round 1 told the operator to `terraform plan -destroy` and stop if buckets appeared — they always would, and the plan errors on `prevent_destroy`. Round 2 documents that error as the safety rail and destroys with `-target=module.kubernetes`, instructing the operator not to remove `prevent_destroy` for a rebuild.
Remediation direction: Keep teardown targeted at the cluster module; move buckets to their own root only if this root grows more non-cluster resources.
Status: Fixed in round 2

### M2-R1-F07  Low  Scalability  Etcd snapshots have no retention
Location: `docs/runbooks/cluster-bootstrap.md:58-60`; `infra/terraform/hetzner/kubernetes.tf:48-56`; `infra/terraform/hetzner/buckets.tf:22-30`
Problem: Daily compressed snapshots still go into a versioned bucket with no Terraform lifecycle rule. Round 2 documents a 30-day console prune until Hetzner lifecycle is apply-tested, and correctly refuses to add an untested `aws_s3_bucket_lifecycle_configuration`.
Remediation direction: After a live apply confirms which lifecycle API Hetzner implements, encode that retention in Terraform or a prune Job.
Status: Fixed in round 2

### M2-R2-F01  Low  Reliability  Backup S3 key pair is not validated together
Location: `infra/terraform/hetzner/variables.tf:142-154`; `infra/terraform/hetzner/kubernetes.tf:51-52`
Problem: `talos_backup_s3_secret_key` “Must be set together with” `talos_backup_s3_access_key`, but there is no `validation` block. `coalesce` on each variable independently means one dedicated key plus one project key can be mixed; the CronJob then authenticates with a split pair and snapshots silently fail (`OnFailure` / `suspend` only if the bucket is null).
Remediation direction: Fail plan unless both optional keys are null or both are non-null.
Status: Open

### M2-R1-F04  Low  Security  ADR-0005 “plan-time” checks do not fail the plan
Location: `infra/terraform/cloudflare/variables.tf:63-82`
Problem: Round 1 used `check` blocks (warn and continue). Round 2 moved notes-api `rate_limit` and grafana/argocd/hubble `public = false` into `variable "hostnames"` validations. Soft `check` blocks are gone from `locals.tf`. A tfvars change that opens an admin host or drops the rate-limit flag now fails plan/apply.
Remediation direction: Keep these as variable validations (or resource preconditions), not `check` blocks.
Status: Fixed in round 2

### M2-R1-F08  Low  Security  Talos-backup uses the project-wide S3 keys
Location: `infra/terraform/hetzner/kubernetes.tf:50-52`; `infra/terraform/hetzner/variables.tf:142-154`; module `talos_backup.tf:21-32` Secret in `kube-system`
Problem: Optional `talos_backup_s3_*` variables exist, but `coalesce` still defaults to `var.s3_access_key` / `var.s3_secret_key`, which also unlock `ivp-tfstate` and `ivp-cnpg`. Example tfvars and bootstrap call a dedicated pair optional. The happy path still puts project-wide Object Storage credentials in `kube-system`. Compromising that namespace is already severe; this remains avoidable extra blast radius.
Remediation direction: Make the dedicated `ivp-etcd` pair required (no coalesce), and document the Hetzner console steps to mint it. Do not default to the keys that can read Terraform state.
Status: Open

### M2-R1-F05  Low  Operability  Bootstrap SOPS steps are bash-only on a Windows workstation
Location: `docs/runbooks/cluster-bootstrap.md:125-145`
Problem: Round 1 used POSIX `/tmp`, `umask`, and `shred`. Round 2 adds a PowerShell path: UTF-8 no BOM, in-place encrypt on the Git path, `Remove-Variable token`. Residual shell-history exposure is stated in the runbook.
Remediation direction: Keep a Windows path next to the bash path whenever the operator workstation is first-class.
Status: Fixed in round 2

### M2-R1-F06  Low  Operability  Bootstrap verification command is a placeholder
Location: `docs/runbooks/cluster-bootstrap.md:49-50`
Problem: Round 1 had a non-runnable `talosctl version --nodes "$(talosctl get members -o json | ...)"`. Round 2 uses `talosctl get members` then `talosctl version --nodes "$(talosctl get members -o jsonpath='{.items[0].metadata.id}')"`, matching `cluster-upgrade.md:22`.
Remediation direction: Keep copy-pasteable jsonpath; do not leave ellipsis placeholders in verify blocks.
Status: Fixed in round 2

### M2-R2-F02  Nit  Operability  Duplicate verify line
Location: `docs/runbooks/cluster-bootstrap.md:51-52`
Problem: `kubectl get nodes -o wide` is written twice. Harmless, but it is leftover from the F06 edit and looks like the verify block was not read back.
Remediation direction: Delete the duplicate line.
Status: Open

## Dimension notes

### Code quality — 8
Two small roots, typed variables with blocking validations, documented outputs, camelCase CSI keys matching the module schema, `terraform fmt` / `validate` / `tflint` clean on both, SHA-pinned `terraform.yml` that only validates. Lockfiles are present and not gitignored. Round-2 hostnames validations actually fail the plan. Remaining gaps are the missing backup-key-pair validation (F01 this round) and the absence of `terraform test` assertions — not spaghetti HCL.

### Scalability — 8
This is a three-node personal cluster; the shape and the 1–8 worker cap are honest. Cloudflare rate-limit and Access exist at the edge. Etcd snapshot growth is now an explicit 30-day console prune (F07 fixed as documentation). No N+1, no metric cardinality bomb in this milestone.

### Reliability — 8
Delete protection on servers and buckets, CCM load balancers off, age-encrypted daily etcd snapshots (ahead of the ADR-0004 “CronJob in M3” line), versioning on buckets, firewall limited to two API ports. Teardown as written can rebuild the cluster without wiping backup buckets (F01). Rate-limit defaults will not bounce a Free zone on `period` (F03). Single control plane is an accepted ADR-0004 consequence; restore remains M3. Residual: a mixed dedicated/project S3 pair can break snapshots without failing plan (M2-R2-F01).

### Future-proofing and migration readiness — 8
Split Hetzner/Cloudflare roots match ADR-0002; S3 backend examples match ADR-0010; hostnames map and 404 catch-all match ADR-0005; module and toolchain pins match ADR-0004/`versions.env`; Actions are SHA-pinned (ADR-0012); Renovate includes the terraform manager. Provider lock-in is confined to the Cloudflare root and hcloud CCM/CSI, as designed. Origin service DNS `cilium-gateway-public.gateway.svc.cluster.local` is a cross-milestone contract with no Gateway object in this repo yet (acceptable for M3, but it is only a variable default).

### Security — 8
API CIDR allow-list, no Hetzner HTTP LB, Access plus origin JWT on admin hostnames, 404 catch-all, sensitive tunnel output, gitignore of state and kubeconfig, CSI LUKS, etcd snapshots encrypted to age, SOPS encrypt on a path `.sops.yaml` actually matches, named Access/rate-limit guards that fail the plan. That is a real design. It is not a 9 because the backup Job still defaults to project-wide S3 keys that can read Terraform state (F08).

### Operability — 8
Bootstrap, upgrade, and teardown runbooks exist with preconditions, verify, and rollback sections; teardown targeting matches `prevent_destroy`; tunnel encrypt has a Windows path; `versions.env` lockstep is written down; CI will fmt/validate/tflint on path filter without cloud credentials. A 3 a.m. operator can follow the written procedures. Residual nits: duplicate `kubectl get nodes` line, and no live plan in the pack.

## What was done well
- One `hostnames` map generates CNAME, tunnel ingress, and Access together, with origin JWT (`origin_request.access`) on non-public hosts and a 404 catch-all — that is the ADR-0005 invariant implemented as data flow, not as a comment. Round 2 made the named admin/rate-limit half of that invariant fail the plan.
- `firewall_use_current_ipv4` is mutually exclusive with an explicit `firewall_api_source`, and an empty CIDR list is rejected, so the module’s concatenate-with-current-IP behaviour cannot silently open the APIs to both.
- CCM and kube-API load balancers are explicitly off (the module defaults CCM LBs **on**), so ADR-0005 is not left to module defaults.
- Etcd snapshots are age-encrypted into `ivp-etcd` in this milestone, with a required `age1…` variable, which is the correct mitigation for the accepted single-CP failure mode even though the CronJob was scheduled for M3 in ADR-0004.
- Teardown now matches HashiCorp’s `prevent_destroy` behaviour instead of contradicting it: targeted destroy of `module.kubernetes`, buckets left as a deliberate survival.
- `terraform.yml` pins Terraform 1.16.2 and TFLint 0.59.1 by SHA, `permissions: contents: read`, and never applies — CI cannot spend cloud money or mutate the edge.
