## Verdict

Overall: 7 — FAIL
Code quality: 7 | Scalability: 7 | Reliability: 6 | Future-proofing: 7 | Security: 8 | Operability: 6

The crypto boundary and the Kubernetes shape are real: the browser derives Argon2id keys, the API hashes `X-Auth` before storage, CNPG+Barman+SOPS+HTTPRoute+NetworkPolicy exist on paper, and httptest covers the happy path. The milestone still fails because the tests that would prove ADR-0009 (Argon2id known-answer vectors, `SHA-256(authProof)` at rest) are a fake KDF, the advertised 20 MiB item cap cannot survive `MaxBytesReader`, and two replicas run unlocked `goose.Up` on boot. The single most important problem is that first deploy of Deployment replicas=2 races migrations with no session lock. Fix that race, add real Argon2id vectors plus a byte/TTL test, and size the HTTP body limit for base64 JSON — that is what moves this to a 9, together with a notebook runbook and a Grafana query that matches the actual `job` label.

## Findings

### M4-R1-F01  High  Reliability  Two replicas run unlocked goose.Up on every start
Location: `apps/notebook-api/internal/migrate/migrate.go:22-32`; `apps/notebook-api/cmd/notebook-api/main.go:41-43`; `k8s/apps/notebook-api/base/deployment.yaml:9`; goose v3.28.0 `provider_options.go` (“If WithSessionLocker is not called, locking is disabled”)
Problem: `main` calls `goose.UpContext` (legacy API, no `WithSessionLocker`) before listen. The Deployment has `replicas: 2` and a default RollingUpdate, so first apply starts two pods that both `CREATE TABLE` against an empty database. goose does not take `pg_advisory_lock` on this path. A lost race leaves `already exists` / a half-applied version row and CrashLoop until luck converges. That is an outage on the first GitOps sync, which is exactly when CNPG is also still bootstrapping.
Remediation direction: Run migrations from one Job or an init container with a session lock (`goose.NewProvider` + `lock.NewPostgresSessionLocker`), and keep the API process migration-free.
Status: Open

### M4-R1-F02  Medium  Reliability  20 MiB item cap is not the wire limit the API enforces
Location: `apps/notebook-api/internal/api/http.go:27,160-186`; `apps/web/src/components/islands/Notes.tsx:99-117`
Problem: `MaxBytesReader` is `MaxItemBytes + 1MiB` (21 MiB) applied to the JSON body. Ciphertext is unpadded base64url, so a 20 MiB item is ~27 MiB on the wire before JSON wrapping; a 20 MiB image is first `btoa`'d inside the envelope, then encrypted, then base64'd again. The handler will return `invalid json` long before `len(ct) > MaxItemBytes`. The island still offers 20 MiB files. ADR-0009’s “item cap 20 MB” is therefore neither usable nor tested.
Remediation direction: Size the reader for base64+JSON overhead (or accept raw bytes), and add an httptest that posts a body just under and just over the configured ciphertext cap.
Status: Open

### M4-R1-F03  Medium  Code quality  No Argon2id known-answer tests; auth_hash storage unasserted
Location: `apps/web/tests/unit/notebook.test.ts:21-38,54-67,92-97`; no test in `apps/notebook-api/internal/api/http_test.go` reads `AuthHash`; `notebook.ts` coverage uncovered line 49
Problem: AC 2 asked for test vectors of Argon2id 64MiB/3/1 with salt SHA-256(`ivanpanev.net/notebook/v1`) and the lookup/auth/enc split. The suite pins the constants and then runs a SHA-256 stand-in named “ADR-0009 vectors with fake KDF”. A hash-wasm regression, a salt encoding bug, or a server that stored `authProof` instead of `SHA-256(authProof)` would all go green. Playwright’s generate-passphrase test exercises real Argon2id only as “did not throw”.
Remediation direction: Commit one known 96-byte Argon2id output for a fixture passcode (run hash-wasm once, pin hex), assert `notebookId`/`authProof`, and in httptest read the store and check `sha256(decoded X-Auth)`.
Status: Open

### M4-R1-F04  Medium  Code quality  Byte, TTL, sweep, extend, and Postgres paths are untested
Location: `apps/notebook-api/internal/api/http_test.go` (no Test for `item too large`, `ttl out of range`, extend, sweep, readyz 503); `internal/store/` has no unit tests; `config_test.go:19-20` omits `MaxNotebookBytes` and TTL bounds
Problem: The milestone’s abuse controls are 20 MiB / 100 MiB / 50 items / 1h–7d. Only a reduced item-count cap is exercised. `internal/store` (including `UpsertNotebook` expiry behaviour) is covered solely by a CI-only integration test that inserts one row. `go test ./...` reports `?` for `store`, `migrate`, `cmd`.
Remediation direction: httptest the 413 and TTL 400 paths at tiny caps; unit-test Memory+Postgres `Upsert`/`Sweep`/`Extend`; keep the integration tag for the real engine.
Status: Open

### M4-R1-F05  Medium  Reliability  PUT cannot recreate an expired notebook until Sweep deletes it
Location: `apps/notebook-api/internal/store/postgres.go:38-61`; `internal/api/http.go:378-396`; `internal/config/config.go:44` (default sweep 1m)
Problem: `ON CONFLICT … WHERE notebooks.expires_at > now()` affects 0 rows on an expired id; the follow-up `SELECT … expires_at > now()` returns `ErrNotFound`, which the API maps to 404. The island’s “Open notebook” is a PUT. For up to `SweepInterval` after TTL, the rightful holder cannot reopen, and a colliding passcode cannot take the slot either. Memory store does not match this (it still finds the row and checks the hash).
Remediation direction: Treat expired-but-present ids as insertable (delete-then-insert in one transaction, or `ON CONFLICT` that replaces when `expires_at <= now()`).
Status: Open

### M4-R1-F06  Medium  Reliability  No retry/backoff on Postgres errors (ADR-0008)
Location: `docs/adr/0008-postgres-via-cloudnativepg.md:45-47`; `apps/notebook-api/internal/api/http.go:289-304`; `cmd/notebook-api/main.go:63-67` (`ReadHeaderTimeout` only)
Problem: ADR-0008 requires services to tolerate single-instance restart with retry and backoff. Handlers map any store error that is not a sentinel to 500 with no retry. There is no statement timeout, no `ReadTimeout`/`WriteTimeout`. Readiness will eventually pull pods from the Service (`readyz` pings with 2s, `deployment.yaml:77-81`), so this is not a CrashLoop, but every in-flight request during a CNPG bounce is a hard failure and the browser `fetch` in `notebook.ts:139-142` has no timeout or retry either.
Remediation direction: Retry idempotent operations (GET/PUT/DELETE/extend) on connection errors with bounded backoff; set server and pgx timeouts; leave POST insert as fail-fast or use an idempotency key.
Status: Open

### M4-R1-F07  Medium  Operability  No notebook-api runbook
Location: `docs/runbooks/README.md:8-18` (table ends at etcd-restore / pgp; restore-drill is M5); `apps/notebook-api/README.md:27-39` is local `go run` only
Problem: An on-call stranger gets ImagePullBackOff until CI publishes, CNPG `-app` secret races the Deployment, WAL dest `s3://ivp-cnpg/notebook`, overlay bump, and “do not apply root-application yet”. None of that is a procedure with preconditions, verify, and rollback. The evidence pack’s operator list is not a runbook.
Remediation direction: Add `docs/runbooks/notebook-api.md`: sync order, expected secret name `notebook-app`, healthz/readyz, overlay digest, what 401 vs empty list means, how to confirm WAL objects without printing keys.
Status: Open

### M4-R1-F08  Medium  Operability  Grafana dashboard `job` selector is almost certainly dark
Location: `k8s/infrastructure/kube-prometheus-stack/resources/dashboard-notebook-api.yaml:20-41`; ServiceMonitor `k8s/apps/notebook-api/base/servicemonitor.yaml:1-16` (no `jobLabel`)

Status: Open

### M4-R1-F09  Medium  Future-proofing and migration readiness  Plaintext `kind` contradicts ADR-0009 storage rule
Location: `docs/adr/0009-notebook-crypto-and-language.md:38-40` (“metadata … inside the ciphertext envelope. The server stores opaque bytes plus size and expiry”); `migrations/001_init.sql:14`; `http.go:113-128,259-267`; threat model `docs/security/notebook-threat-model.md:16`
Problem: `kind` is a CHECK-constrained column and is returned unauthenticated on list/get. The envelope also carries `kind`. The threat model accepts this as “low”, but the accepted ADR was not revised. This is a documentation/ADR drift, not a decrypt capability.
Remediation direction: Either stop persisting/returning `kind` (client decrypts to label the list) or amend ADR-0009 to allow opaque `kind` as a storage hint.
Status: Open

### M4-R1-F10  Medium  Scalability  Per-IP limiter map never evicts
Location: `apps/notebook-api/internal/api/http.go:34,353-366,432-443`
Problem: `sync.Map` of `ip -> *rate.Limiter` grows with every distinct `CF-Connecting-IP` / `X-Forwarded-For` / RemoteAddr and is never pruned. Cloudflare already caps `/v1/*`; this map is the application’s 10×/100× leak. Spoofed `X-Forwarded-For` when `CF-Connecting-IP` is absent also creates junk keys (F14).
Remediation direction: Bound the map (LRU, or periodically delete limiters at full burst) and key only on a trusted hop (Gateway/`CF-Connecting-IP` after you know cloudflared set it).
Status: Open

### M4-R1-F11  Low  Future-proofing and migration readiness  Floating image tags on Cluster and Dockerfile bases
Location: `k8s/apps/notebook-api/base/cluster.yaml:8` `ghcr.io/cloudnative-pg/postgresql:18`; `apps/notebook-api/Dockerfile:2,11`; overlay still `newTag: main` until CI bump (`overlays/hetzner/kustomization.yaml:5-8`)
Problem: ADR-0012 wants digest-pinned deploys for *our* image after the overlay bump; that path is designed. The CNPG catalog tag `:18` and unpinned `golang` / `distroless` FROM lines can move underfoot. `IfNotPresent` + `:main` means a node that pulled `:main` once will not see a later `main` if the bump job fails.
Remediation direction: Pin the CNPG image by digest (or ImageCatalog); digest-pin Dockerfile bases; keep overlay at `tag@sha256:…` as the workflow already intends.
Status: Open

### M4-R1-F14  Low  Security  `/metrics` is on the public HTTPRoute; client IP headers are trusted

## Dimension notes

### Code quality — 7
Handlers, store, and the island are readable and small. httptest hits health, auth mismatch, round-trip, CORS, count cap, OpenAPI, and 429. That is competent. It is not 8 because the two tests the milestone is *for* — Argon2id vectors and the 20 MiB / TTL caps — are missing or faked, `internal/store` is `?` under `go test ./...`, and `Notes.tsx` has zero unit coverage. golangci-lint was not re-run here (`could not execute: golangci-lint`).

### Scalability — 7
Caps, token bucket, and Cloudflare `/v1/*` 10/10s are the right shape for a personal notebook. Postgres `bytea` for 100 MiB notebooks is accepted (OD-7). The limiter `sync.Map` is the 100× leak; two replicas do not share the bucket (effective 2×, Cloudflare still wins). Item list is unpaginated but hard-capped at 50. Metric labels are bounded route names, not raw paths.

### Reliability — 6
Liveness vs readiness is correct (`/healthz` vs `/readyz`+Ping), shutdown is 15s, InsertItem uses `FOR UPDATE`, sweeper and `expires_at` indexes exist, single-instance CNPG is an accepted ADR-0008 cost. It drops to 6 on F01 (boot migration race on replicas=2), F02 (advertised 20 MiB uploads fail), F05 (expired PUT 404), and F06 (no backoff through a CNPG bounce). Happy-path httptest does not exercise any of those.

### Future-proofing and migration readiness — 7
Go + pgx + embedded goose + S3 ObjectStore + overlay digest bump match ADR-0008/0010/0012/0013. `TARGETARCH` is in the Dockerfile. Drift: plaintext `kind` vs ADR-0009, floating CNPG `:18`, OTel not actually exported. WAL to `ivp-cnpg/notebook` is the migration handle; restore drill is correctly out of scope (M5).

### Security — 8
The thing that matters works in code: passcode never leaves the browser, `auth_hash = SHA-256(decoded authProof)`, AES-256-GCM with random 96-bit nonces, constant-time compare on POST, CORS allowlist with a negative test, PSA restricted, non-root distroless, no service account token, GOMEMLIMIT, threat model with numbers and an honest collision paragraph. SHA-pinned Actions. Residual: public `/metrics`, spoofable forwarding headers, `kind` on the unauthenticated list, hash-wasm `^` range, no live cosign. None of that decrypts notebooks. Not a 9 until vectors pin the KDF and metrics leave the public route.

### Operability — 6
JSON slog, `/metrics`, ServiceMonitor, dashboard ConfigMap, CNPG PodMonitor, and a README for local `go run` exist. There is no cluster runbook, the dashboard PromQL is wrong, traces have nowhere to go, `LOG_LEVEL` is ignored, and first GitOps boot is ImagePullBackOff plus a migration race. That is not operable at 03:00.

## What was done well
- ADR-0009 revision is implemented in the write path: `auth_hash = sha256.Sum256(decoded X-Auth)` and POST uses `subtle.ConstantTimeCompare` (`http.go:94,154-157`), not storage of `authProof` or `SHA-256(authKey)`.
- GET list returns an empty array for unknown ids (`http.go:102-128`, `TestWrongPasscodeLooksEmpty`), so a wrong passcode is not an existence oracle on the read path.
