## Findings

### M5-R1-F01  High  Reliability  LokiObjectStoreErrors still would not have fired on the M3 Access Denied outage
Location: `k8s/infrastructure/kube-prometheus-stack/resources/platform-alerts.yaml:118-127`; `k8s/infrastructure/loki/values.yaml:32-34` (`use_thanos_objstore: true`; helm template of chart 18.11.7 emits the same); Grafana Loki docs “Object store operations” name `loki_objstore_bucket_operation_failures_total` / `loki_objstore_bucket_operations_total`; M3 evidence `docs/reviews/m3-r2.md:22,40-42` (`loki-0` 1/1 Ready, `upload s3 object: Access Denied`); Loki ServiceMonitor enabled (`loki/values.yaml:121-124`)
Problem: Round 2 used `loki_s3_*` / `thanos_objstore_*`, which this Thanos-client cluster does not export. Round 3’s first clause is `sum(rate(loki_objstore_bucket_operation_failures_total[10m])) > 0`. That is the documented Thanos-objstore failure counter; an Access Denied on `upload` increments it while the StatefulSet can stay Ready, which is the M3 signature. LokiNotReady remains the crash/restart rule (`platform-alerts.yaml:109-117`). Live series were not scraped here (sandbox); that is operator-verify, not a fail.
Remediation direction: Keep the `loki_objstore_*` failure counter; optionally drop the dead `status_code` matcher (M5-R3-F01).
Status: Fixed in round 3

### M5-R1-F03  Medium  Reliability  Restore `isWALArchiver: false` is a CI string, not a runtime WAL guard
Location: `k8s/apps/notebook-restore/cluster.yaml:6-7,8-45` (annotation `cnpg.io/skipWalArchiving: enabled`, no `spec.plugins`); `objectstore.yaml:1-2,10`; `scripts/k8s-validate.sh:17-28`; `docs/runbooks/restore-drill.md:4-6,65`; CNPG annotation docs / PR #4055 (`archive_mode=off` when set to `enabled`); pgEdge CNPG 1.30 labels_annotations
Problem: Round 2 set `plugins[].isWALArchiver: false`, which CNPG 1.30 `innerArchiveWAL` does not read. Round 3 removes `spec.plugins` (no WAL-capable sidecar) and sets the operator annotation that disables WAL archiving at runtime. CI fails if the annotation is missing, if `plugins:` appears on the Cluster, or if `isWALArchiver: true` appears under the overlay. Rendered build matches. Copying the live PutObject key remains BACKLOG (no second AK); not reopened as High.
Remediation direction: Mint a list/get-only restore key when a second AK exists; keep the skip annotation and no-plugins CI lock.
Status: Fixed in round 3

## Dimension notes

### Code quality — 8
Restore overlay, platform rules, and gates are small and named for their job. Secret clone is still an explicit `apiVersion/kind/metadata/data` rewrite (`restore-drill.sh:29-38`). `k8s-validate.sh` now asserts the real WAL controls, not a greppable `false`. `check-alerts.sh` remains heading-and-annotation only; this round’s PromQL was checked against Grafana/CNPG docs instead. The leftover `status_code` matcher (M5-R3-F01) is dead but does not empty the Loki rule. No Report-Only CSP path.

### Scalability — 8
Phase 1 load does not stress these artifacts. PVCNearFull is a ratio per volume; NodePressure is per node; notebook-api histograms still `sum by (le)`. Restore adds one 10Gi PVC and is still documented as a cost leak if left behind (`docs/cost.md:30`). Cardinality of Loki/WAL rules is one Loki job / one CNPG cluster. Fine at 10×; 100× remains the ADR-0007 Prometheus/Loki retention discussion.

### Reliability — 8
The M3 Ready-pod PutObject 403 now has a first-class rule on the Thanos-client series this cluster actually runs (`use_thanos_objstore: true`, Grafana `loki_objstore_*`). WAL lag uses exported CNPG 1.30 names, so RPO minutes (ADR-0004/0008) are not solely the 36h base-backup window. Restore runtime WAL is `archive_mode=off` plus no plugin sidecar, CI-enforced. CertificateExpiring still joins `on(namespace, name)` with a scrape Prometheus will select. Live restore and live series remain operator-verify; that is not a fail.

### Future-proofing and migration readiness — 8
No ADR deviation. Restore is still not in `k8s/clusters/hetzner`. ObjectStore endpoint/bucket stay configuration (ADR-0008/0010). Migration reds are only home-cluster items. Threat model still records write-to-`main` ≡ cluster-admin via KSOPS `--enable-exec` (ADR-0006). Overlay still deploys `:main` until first CI digest (yellow #7). Unpinned `postgresql:18` on live and restore remains Low (F06 / M4-R1-F11).

### Security — 8
CSP is still enforce on both channels. `check-dist.mjs` will demand `security.txt.asc` once `publickey.asc` exists. Threat model is specific on PAB, Loki versioning, KSOPS exec, and now names LokiObjectStoreErrors for the 403 trap. Restore overlay is not GitOps-synced. The copied production S3 secret is BACKLOG, not a public-site exposure; skipWalArchiving + no plugins is the WAL write control this round required.

### Operability — 8
`incidents.md` has one section per platform alert, including LokiObjectStoreErrors that greps AccessDenied while Ready and a WAL section that tells you not to wait for 02:00. Restore runbook checks the skip annotation and no `spec.plugins`. Cost and PVC runbook name Alertmanager 2Gi. ## What was done well
- Restore WAL is disabled with the CNPG control that actually sets `archive_mode=off` (`cnpg.io/skipWalArchiving: enabled`), not a plugin flag the 1.30 WAL client ignores, and `k8s-validate.sh:17-28` fails closed on a missing annotation or a `spec.plugins` sidecar.
- `LokiObjectStoreErrors` uses `loki_objstore_bucket_operation_failures_total`, which is the Grafana-documented Thanos-client series; helm render of this chart with these values emits `use_thanos_objstore: true`. That is the M3 Ready-pod 403 class, not a pod-not-ready proxy.
- `CNPGWALArchivingStuck` uses `cnpg_pg_stat_archiver_seconds_since_last_archival` and `cnpg_collector_pg_wal_archive_status{value="ready"}` (a count of `.ready` segments), matching CNPG 1.30 default monitoring rather than the collector prefix the file header warns stays at 0 for plugin backups.
- Restore remains a manual overlay with independent “do not GitOps this” comments, and `k8s/clusters/hetzner` still does not reference it; a second writer on `s3://ivp-cnpg/notebook` cannot appear from Argo.
- CertificateExpiring still joins `on(namespace, name)` with ServiceMonitor `:9402` and `serviceMonitorSelectorNilUsesHelmValues: false`, so the rule can actually scrape.
- CSP remains enforce-only hash meta plus `_headers` `frame-ancestors 'none'`, with `check-dist.mjs` as the gate.
- Platform threat model states the KSOPS `--enable-exec` trust boundary in the same words as ADR-0006 and now routes the Loki PAB/versioning trap to LokiObjectStoreErrors.
