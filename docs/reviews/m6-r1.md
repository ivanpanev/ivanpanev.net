## Verdict

Overall: 7 — FAIL
Code quality: 7 | Scalability: 8 | Reliability: 7 | Future-proofing: 7 | Security: 8 | Operability: 7

The GitOps shape is the right one: CNPG+Barman is a copy of the notebook pattern with a distinct S3 prefix, the overlay is an Argo Application (unlike notebook-restore), Access/`public = false` is in the Terraform invariant, and helm template 2026.8.2 emits no Redis, no Bitnami Postgres, no GeoIP. The milestone does not actually wire Authentik to that database. Setting `authentik.existingSecret.secretName` makes the chart ignore `authentik.postgresql.host: authentik-rw`; the SOPS secret only has `AUTHENTIK_SECRET_KEY` and `AUTHENTIK_POSTGRESQL__PASSWORD`, so the process defaults to `localhost` and will CrashLoop after the first GitOps sync. That single High caps the score at 7. Fix the host (and stop treating `authentik.postgresql.*` as live config under `existingSecret`), then the rest is an 8 with nits.

## Findings

### M6-R1-F01  High  Reliability  existingSecret discards `authentik-rw`; pods default Postgres to localhost
Location: `k8s/apps/authentik/values.yaml:7-19`; `k8s/apps/authentik/resources/authentik-config.secret.yaml:7-9`; `helm template authentik authentik --repo https://charts.goauthentik.io --version 2026.8.2 --namespace authentik -f k8s/apps/authentik/values.yaml` (server/worker: empty `env:`, only `envFrom.secretRef.name: authentik-config`; no chart Secret rendered); chart `templates/secret.yaml` skipped when `existingSecret.secretName` is set; chart values comment “when set, authentik.* secret values are ignored”; Authentik `default.yml` `postgresql.host: localhost` (tag `version-2026.8`)
Problem: `authentik.postgresql.host: authentik-rw` never becomes `AUTHENTIK_POSTGRESQL__HOST`. The SOPS secret carries only `AUTHENTIK_SECRET_KEY` and `AUTHENTIK_POSTGRESQL__PASSWORD`. With bundled Postgres off, the server/worker will try `localhost:5432`, fail health on `/-/health/ready/`, and AuthentikDown will fire after GitOps sync even though Cluster `authentik` is correctly defined. This is the first-sync outage for the component this milestone exists to ship.
Remediation direction: Inject `AUTHENTIK_POSTGRESQL__HOST=authentik-rw` (and user/name if you do not want to rely on image defaults) via `global.env` / `server.env` / `worker.env`, or put those keys in `authentik-config`. Treat `authentik.postgresql.*` under `existingSecret` as dead. Confirm logs connect to `authentik-rw`, not localhost.
Status: Open

### M6-R1-F02  Medium  Reliability  Postgres password is authored twice and can drift
Location: `k8s/apps/authentik/resources/authentik-config.secret.yaml:9` (`AUTHENTIK_POSTGRESQL__PASSWORD`); `authentik-db.secret.yaml:8-9` (`username`/`password`); `cluster.yaml:16-18` (`bootstrap.initdb.secret.name: authentik-db`); `docs/adr/0008-postgres-via-cloudnativepg.md:31-32`; contrast `k8s/apps/notebook-api/base/deployment.yaml:50-54` (`notebook-app` / `uri`)
Problem: CNPG owner credentials and Authentik’s DB password are two independently encrypted values. Rotation or a KSOPS re-encrypt that updates only one secret yields a Ready Cluster and a CrashLooping IdP. Notebook already consumes the operator-generated `-app` Secret; this overlay does not.
Remediation direction: Omit `bootstrap.initdb.secret`, let CNPG mint `authentik-app`, and `secretKeyRef` that `password` into `AUTHENTIK_POSTGRESQL__PASSWORD`. Keep SOPS for `AUTHENTIK_SECRET_KEY` (and S3) only.
Status: Open

### M6-R1-F03  Medium  Operability  `checksum/secret` is SHA-256 of an empty template, so SOPS rotation does not roll pods
Location: `helm template` annotation `checksum/secret: 01ba4719c80b6fe911b091a7c05124b64eece964e09c058ef8f9805daca546b` on `authentik-server` and `authentik-worker` (SHA-256 of empty string); chart `templates/server/deployment.yaml` / `templates/worker/deployment.yaml` checksum over `templates/secret.yaml`, which renders nothing when `existingSecret` is set
Problem: Changing `authentik-config` (secret_key or DB password) updates the Secret in-cluster via KSOPS but does not change the Deployment fingerprint. Kubernetes will not restart the processes. Combined with F02, a partial rotation can leave one replica on the old password indefinitely.
Remediation direction: Annotate both Deployments with a checksum of the KSOPS secret (or a values-file hash), or document a mandatory `kubectl rollout restart` in `docs/runbooks/secrets.md` / `authentik.md` for this pair.
Status: Open

### M6-R1-F04  Low  Security  Worker ServiceAccount can mutate Secrets, Deployments, and HTTPRoutes in-namespace
Location: `helm template` Role `authentik` (`get/create/delete/list/patch` on secrets, services, configmaps, deployments, ingresses, httproutes, servicemonitors); worker Deployment `serviceAccountName: authentik`; `values.yaml` does not set `serviceAccount.create: false`. NetworkPolicy still allows those pods `0.0.0.0/0:443` (`networkpolicy.yaml:45-50`).
Problem: That Role is the managed-outpost helper. This milestone deploys no outposts. A worker RCE can read `authentik-config` / `cnpg-s3` and egress them. Chart default, not a new hole, but it is extra privilege on an IdP.
Remediation direction: Set `serviceAccount.create: false` until an outpost milestone needs it, or split a Role that cannot get secrets.
Status: Open

### M6-R1-F05  Low  Future-proofing  Authentik Cluster floats `postgresql:18` (M4-R1-F11 now on a second live database)
Location: `k8s/apps/authentik/resources/cluster.yaml:8`; BACKLOG `M4-R1-F11` / `M5-R1-F06`
Problem: A catalog republish can move live `authentik` onto a different `:18` digest than the Barman backup, independent of notebook. Same unpinned tag, new blast radius.
Remediation direction: Pin authentik (and notebook/restore) to the same digest or image catalog before the first authentik backup is treated as restorable.
Status: Open

### M6-R1-F06  Low  Operability  CNPG backup/WAL incident checks still only name the notebook namespace
Location: `docs/runbooks/incidents.md:52-56,118-121`; alerts `platform-alerts.yaml:35-54,78-87` (labeled by `cluster`, so they will fire for `authentik`)
Problem: On-call following CNPGBackupMissing / CNPGWALArchivingStuck after Authentik is live will `kubectl -n notebook` and `s3 ls s3://ivp-cnpg/notebook/` while the failing cluster is `authentik`.
Remediation direction: Parameterise those Check blocks by `$labels.namespace` / `$labels.cluster`, and list `s3://ivp-cnpg/authentik/` beside notebook.
Status: Open

### M6-R1-F07  Nit  Operability  Architecture mermaid omits `auth.` from the tunnel hostname list

Problem: The diagram still reads `notes-api., grafana., argocd., hubble.` into the tunnel. Auth is drawn from Gateway but a reader of the edge line would think `auth.` is unpublished.
Remediation direction: Add `auth.` to that Cloudflare→Tunnel label.
Status: Open

## Dimension notes

### Code quality — 7
Kustomize/Argo layout matches notebook, Terraform typing and hostname validation are real, and `check-alerts.sh` is a gate rather than a comment. The values file documents a CNPG host that the chart will not honour (`values.yaml:3,14-15` vs `existingSecret` at `:10-11`), and kubeconform cannot see that. No unit/CI assertion covers `AUTHENTIK_POSTGRESQL__HOST`. That is a competent overlay with one structural miss, not messy code.

### Scalability — 8
One server, one worker, one CNPG instance, requests 512Mi+512Mi+256Mi and 10Gi volume match ADR-0016’s ~2 GiB / €0.50 sketch. HPA is off; ServiceMonitor cardinality is one scrape. Friends-and-family IdP load is nowhere near a 10x problem. Horizontal scale is a one-line replica change plus `instances: 2` when a later milestone needs it.

### Reliability — 7
Barman plugin, 30d retention, nightly `02:00`, checksum env on the Cluster, and CNPG backup/WAL alerts that are cluster-labeled are the same path that passed M5. Probes, startupProbe 60×10s, and AuthentikDown exist. None of that matters if the app never reaches `authentik-rw` (F01). Dual-authored DB passwords (F02) and a no-op rollout checksum (F03) are the next failure modes after host is fixed. Single-replica / `enablePDB: false` is the accepted Phase 1 CNPG posture.

### Future-proofing and migration readiness — 7
Chart 2026.8.2 / appVersion 2026.8.2, Postgres-only (no Redis, ADR-0010), restore story is “same drill, `serverName: authentik`”, S3 endpoint is configuration. ADR-0016 and ADR-0005 hold; federation is correctly deferred. The overlay still does not use the CNPG `-app` Secret ADR-0008 names, and it inherits floating `postgresql:18`. Migration of identity state is possible only after F01 and a first backup.

### Security — 8
`auth` cannot be made public without failing `terraform validate`; origin JWT is the same `origin_request.access` loop as Grafana/Argo/Hubble; HTTPRoute has no `public` escape hatch. SOPS encrypts `stringData` to operator + `argocd_hetzner` age keys. Namespace is PSA restricted; rendered containers are non-root, drop ALL, RuntimeDefault. GeoIP/Sentry off (image default false; values also false). Worker SA + unrestricted HTTPS egress is extra privilege, not an open admin surface: Access still sits in front. Federation out of scope is recorded, not silently skipped.

### Operability — 7
`docs/runbooks/authentik.md` has preconditions, bootstrap, verify, restore pointer, rollback, and an explicit non-goals list; AuthentikDown is in incidents.md; `check-alerts.sh` is green. The 3 a.m. path after first sync will be “CrashLoop, Cluster Ready” and the runbook’s “CrashLoop on Postgres → CNPG `authentik-rw`” will send the operator at a healthy database (F01). Secret rotation will not bounce pods (F03). CNPG runbooks still say `-n notebook` (F06). Live initial-setup is correctly left as operator-verify.

## What was done well
- Hostname `auth` is one map entry that creates DNS, tunnel ingress, Access app, and origin JWT (`variables.tf:77-82`, `tunnel.tf:24-36`). Forgetting the HTTPRoute 404s; making it public fails validate. That is the ADR-0005 invariant applied, not a one-off record.
- `k8s/apps/authentik` is two Argo Applications on waves 3/4 in `clusters/hetzner`; `notebook-restore` is not. The milestone’s “unlike notebook-restore” constraint is implemented in the app-of-apps list, not a comment.
- Helm 2026.8.2 with this values file really is Postgres-only: 10 rendered objects, Service `authentik-server:80→9000`, image `ghcr.io/goauthentik/server:2026.8.2`, no Redis, no Bitnami Postgres, no GeoIP sidecar. NetworkPolicy port 9000 matches the pod, not the Service.
- CNPG ObjectStore/ScheduledBackup/WAL sidecar env (`AWS_REQUEST_CHECKSUM_CALCULATION=when_required`) is the M3 Hetzner Ceph lesson copied onto a second prefix instead of a new backup scheme.
- ADR-0016 states federation of Access/Grafana/Argo is a later milestone; the runbook repeats that. The critic was not invited to fail the IdP for not being the edge IdP yet.
