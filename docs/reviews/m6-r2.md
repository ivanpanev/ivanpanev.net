## Findings

### M6-R1-F01  High  Reliability  existingSecret discards `authentik-rw`; pods default Postgres to localhost
Location: `k8s/apps/authentik/values.yaml:8-25`; `helm template authentik authentik --repo https://charts.goauthentik.io --version 2026.8.2 --namespace authentik -f k8s/apps/authentik/values.yaml` (server `templates/server/deployment.yaml` env: `AUTHENTIK_POSTGRESQL__HOST=authentik-rw`, `NAME=authentik`, `PORT=5432`, `USER`/`PASSWORD` `secretKeyRef` `name: authentik-app` keys `username`/`password`, plus `envFrom.secretRef.name: authentik-config`; identical block on worker); `scripts/k8s-validate.sh:29-32`
Problem: Round 1: `authentik.postgresql.host` never became process env under `existingSecret`, so server/worker would have used image default `localhost:5432` and CrashLooped after first GitOps sync. Round 2 wires host/name/port/user/password as `global.env`; helm template shows those keys on both Deployments. This is not envFrom-only.
Remediation direction: Keep treating `authentik.postgresql.*` as dead under `existingSecret`. Confirm live logs connect to `authentik-rw`, not localhost.
Status: Fixed in round 2

### M6-R1-F02  Medium  Reliability  Postgres password is authored twice and can drift
Location: `k8s/apps/authentik/resources/cluster.yaml:13-16` (`bootstrap.initdb` database/owner only; no `secret.name`); `authentik-config.secret.yaml:7-8` (`AUTHENTIK_SECRET_KEY` only); no `authentik-db.secret.yaml` in the tree; `values.yaml:16-25` `secretKeyRef` `authentik-app`; `docs/adr/0008-postgres-via-cloudnativepg.md:31-32`
Problem: Round 1 had independently encrypted CNPG owner credentials and Authentik’s DB password. Rotation of one secret would leave a Ready Cluster and a CrashLooping IdP. Round 2 omits `bootstrap.initdb.secret`, lets CNPG mint `authentik-app`, and injects `username`/`password` from that Secret. SOPS no longer carries a Postgres password.
Remediation direction: Rotate the DB password only via CNPG, then restart the Authentik Deployments as the runbook already says.
Status: Fixed in round 2

### M6-R1-F03  Medium  Operability  `checksum/secret` is SHA-256 of an empty template, so SOPS rotation does not roll pods
Location: helm template annotations on `authentik-server` and `authentik-worker`: `checksum/secret: 01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b` (unchanged empty-template hash) **and** `ivp.net/config-epoch: "1"`; `values.yaml:55-58,79-80`; `docs/runbooks/authentik.md:52-64`; `docs/runbooks/secrets.md:148-151`
Problem: Round 1: changing `authentik-config` did not change the Deployment fingerprint. Round 2 still has the chart’s empty checksum (expected under `existingSecret`) but adds a bumpable podAnnotation on both workloads and a mandatory bump-or-`rollout restart` in both runbooks. Forgetting the bump still leaves processes on the old `AUTHENTIK_SECRET_KEY` until restart; that is now an on-call step, not a silent miss.
Remediation direction: Prefer hashing the KSOPS secret into the annotation later so rotation cannot be forgotten; until then follow the runbook.
Status: Fixed in round 2

### M6-R1-F04  Low  Security  Worker ServiceAccount can mutate Secrets, Deployments, and HTTPRoutes in-namespace
Location: `k8s/apps/authentik/values.yaml:41-42` `serviceAccount.create: false`; `helm template` wrote five objects only (`server/deployment`, `worker/deployment`, `server/service`, `server/metrics`, `server/servicemonitor`); grep of the render has no `kind: Role`, `ClusterRole`, `RoleBinding`, `ClusterRoleBinding`, or `ServiceAccount`; neither Deployment sets `serviceAccountName`
Problem: Round 1 rendered the managed-outpost Role (`get/create/delete/list/patch` on secrets and HTTPRoutes) on a worker that this milestone does not need. That Role is gone. Pods use the namespace `default` ServiceAccount. HTTPS egress `0.0.0.0/0:443` remains (`networkpolicy.yaml:45-50`) but without extra RBAC it is not the same hole.
Remediation direction: Leave `serviceAccount.create: false` until an outpost milestone needs a dedicated SA; add a tight Role then, not the chart default.
Status: Fixed in round 2

### M6-R1-F05  Low  Future-proofing  Authentik Cluster floats `postgresql:18` (M4-R1-F11 now on a second live database)
Location: `k8s/apps/authentik/resources/cluster.yaml:8`; BACKLOG `M4-R1-F11` / `M5-R1-F06`
Problem: A catalog republish can move live `authentik` onto a different `:18` digest than the Barman backup, independent of notebook. Same unpinned tag, new blast radius.
Remediation direction: Pin authentik (and notebook/restore) to the same digest or image catalog before the first authentik backup is treated as restorable.
Status: Open

### M6-R1-F06  Low  Operability  CNPG backup/WAL incident checks still only name the notebook namespace
Location: `docs/runbooks/incidents.md:52-57,121-125`
Problem: Round 1 Check blocks said `kubectl -n notebook` and `s3 ls s3://ivp-cnpg/notebook/` while alerts are labeled by `cluster` and will fire for `authentik`. Round 2 parameterises the namespace/cluster from alert labels and lists both S3 prefixes.
Remediation direction: Keep both prefixes when a third CNPG cluster appears.
Status: Fixed in round 2

### M6-R1-F07  Nit  Operability  Architecture mermaid omits `auth.` from the tunnel hostname list
Location: `docs/architecture.md:12` vs host table `:56`
Problem: Round 1 diagram listed `notes-api., grafana., argocd., hubble.` into the tunnel. Round 2 line 12 is `notes-api., grafana., argocd., hubble., auth.`
Remediation direction: Keep the mermaid hostname list in lockstep with the host table.
Status: Fixed in round 2

### M6-R1-F08  Nit  Operability  cost.md and platform-threat-model.md titles still say Milestone 5
Location: `docs/cost.md:1`; `docs/security/platform-threat-model.md:1`
Problem: Round 1 bodies were updated for Authentik but titles still claimed M5. Both titles now say “updated Milestone 6”.
Remediation direction: Retitle when the next milestone changes the inventory.
Status: Fixed in round 2

### M6-R2-F01  Nit  Code quality  HOST CI gate greps values.yaml, not the rendered env
Location: `scripts/k8s-validate.sh:29-32`
Problem: The gate is `grep -q 'AUTHENTIK_POSTGRESQL__HOST' k8s/apps/authentik/values.yaml`. A comment containing that string would pass even if `global.env` were removed. Round 1’s actual bug was “dead values vs process env”; this assertion does not look at `helm template` output. Independent helm template this round still proves the wiring.
Remediation direction: Fail `k8s-validate.sh` unless the authentik helm render contains `AUTHENTIK_POSTGRESQL__HOST` with value `authentik-rw` and `secretKeyRef.name: authentik-app` on both Deployments.
Status: Open

## Dimension notes

### Code quality — 8
Kustomize/Argo layout still matches notebook; Terraform hostname validation is real; `check-alerts.sh` remains a gate. Dead `authentik.postgresql.host` is gone; `global.env` is the live config and helm template agrees. The new HOST grep is a useful tripwire but a substring match on the values file, not on the rendered Deployments (M6-R2-F01). That is a nit on the regression test, not a second structural miss.

### Scalability — 8
One server, one worker, one CNPG instance, requests 512Mi+512Mi+256Mi and 10Gi volume match ADR-0016’s ~2 GiB / €0.50 sketch. HPA is off; ServiceMonitor cardinality is one scrape (server metrics only). Friends-and-family IdP load is nowhere near a 10x problem. Horizontal scale is a one-line replica change plus `instances: 2` when a later milestone needs it.

### Reliability — 8
Barman plugin, 30d retention, nightly `02:00`, checksum env on the Cluster, and CNPG backup/WAL alerts that are cluster-labeled remain the M5 path. Probes, startupProbe 60×10s, and AuthentikDown exist. App→DB wiring now reaches the process (F01/F02). The chart `checksum/secret` is still a no-op; rotation depends on bumping `ivp.net/config-epoch` or `rollout restart`, which is documented (F03). Single-replica / `enablePDB: false` is the accepted Phase 1 CNPG posture. First Helm sync can CreateContainerConfigError until CNPG mints `authentik-app`; wave 3 then 4 makes that a retry, not a design hole (same as notebook-api).

### Future-proofing and migration readiness — 8
Chart 2026.8.2 / appVersion 2026.8.2, Postgres-only (no Redis, ADR-0010), restore story is “same drill, `serverName: authentik`”, S3 endpoint is configuration. ADR-0016 and ADR-0005 hold; federation is correctly deferred. The overlay now consumes the CNPG `-app` Secret ADR-0008 names. Floating `postgresql:18` is unchanged (F05) and is the reason this is not a 9. Migration of identity state is possible after the first backup.

### Security — 8
`auth` cannot be made public without failing `terraform validate`; origin JWT is the same `origin_request.access` loop as Grafana/Argo/Hubble; HTTPRoute has no `public` escape hatch. SOPS encrypts `stringData` to operator + `argocd_hetzner` age keys; the DB password is not in Git. Namespace is PSA restricted; rendered containers are non-root, drop ALL, RuntimeDefault. GeoIP/Sentry off. The outpost Role is gone. Remaining HTTPS egress is the process needing 443, not an admin surface: Access still sits in front. Federation out of scope is recorded, not silently skipped.

### Operability — 8
`docs/runbooks/authentik.md` has preconditions, bootstrap, verify (including “logs must mention `authentik-rw`”), restore pointer, rollback, secret rotation, and an explicit non-goals list. AuthentikDown is in incidents.md; CNPG Check blocks name both prefixes; `check-alerts.sh` is green. Titles on cost and threat-model match M6. Live initial-setup is correctly left as operator-verify. The 3 a.m. secret_key path is “bump epoch or rollout restart”, which an on-call stranger can follow.

## What was done well
- `global.env` is not documentation: helm template 2026.8.2 puts `AUTHENTIK_POSTGRESQL__HOST=authentik-rw` and `secretKeyRef` `authentik-app` on **both** server and worker, with `envFrom` only for `AUTHENTIK_SECRET_KEY`. That is the round-1 failure mode actually closed.
- Postgres credentials follow ADR-0008: CNPG mints `authentik-app`; Git holds no DB password. Notebook already did this with `notebook-app`/`uri`; Authentik now matches instead of inventing a parallel SOPS user.
- Hostname `auth` is one map entry that creates DNS, tunnel ingress, Access app, and origin JWT (`variables.tf:77-82`, `tunnel.tf:24-36`). Forgetting the HTTPRoute 404s; making it public fails validate.
- `k8s/apps/authentik` is two Argo Applications on waves 3/4 in `clusters/hetzner`; `notebook-restore` is not. Helm 2026.8.2 with `serviceAccount.create: false` really is five objects: no Redis, no Bitnami Postgres, no GeoIP, no outpost Role.
- CNPG ObjectStore/ScheduledBackup/WAL sidecar env (`AWS_REQUEST_CHECKSUM_CALCULATION=when_required`) is the M3 Hetzner Ceph lesson copied onto a second prefix instead of a new backup scheme.
- ADR-0016 states federation of Access/Grafana/Argo is a later milestone; the runbook repeats that. The critic was not invited to fail the IdP for not being the edge IdP yet.
